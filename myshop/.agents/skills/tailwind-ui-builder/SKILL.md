# Tailwind UI Builder

## Core Rule

The technical assignment controls what screens and features exist. The Hop & Barley reference controls only visual direction.

Do not infer product rules, checkout rules, categories, or backend behavior from the visual reference.

## UI Principles

- Build the actual usable page, not a marketing placeholder.
- Use Django template structure first; style with Tailwind utility classes.
- Keep UI dense enough for ecommerce browsing and management workflows.
- Use responsive layouts with stable dimensions for cards, grids, controls, and media.
- Make forms readable, accessible, and clear about validation errors.
- Use Alpine.js only for UI state such as menus, disclosure panels, tabs, filters, or quantity controls.

## Visual Direction

When the Hop & Barley reference is available, translate it into:

- Typography scale.
- Spacing rhythm.
- Color tokens.
- Button and link style.
- Product/listing card style.
- Header, navigation, and footer feel.

Do not copy text, data, logos, proprietary imagery, or unapproved behavior.

## HTMX-Friendly UI

- Design partials that can stand alone when swapped into the page.
- Include loading, empty, error, and success states.
- Keep swapped regions stable to avoid layout jumps.
- Ensure controls remain keyboard accessible.

## Output Expected From This Skill

When asked to design UI, produce:

- Page layout plan.
- Tailwind component structure.
- Responsive behavior.
- Template partials needed.
- Alpine.js state, if any.
- Accessibility notes.
